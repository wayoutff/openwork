# Локальная разработка форка

## Запуск

Готовая команда для текущего расположения репозитория:

```bash
bash "$HOME/Downloads/homelab/openwork/scripts/dev-local.sh"
```

Из корня репозитория: `bash scripts/dev-local.sh`.
Остановка: `Ctrl+C` в терминале запуска. Скрипт не устанавливает зависимости
и не меняет default-версию Node. Он выбирает `.nvmrc` через существующий nvm,
использует Corepack и запускает Electron с теми же параметрами изоляции, что
`dev:worktree`, но фиксированным портом интерфейса `15373`. Это сохраняет
localStorage настроек между запусками. При конфликте порт можно переопределить
через `OPENWORK_LOCAL_DEV_PORT`; новый origin получит отдельные UI-настройки.

Dev-профиль имеет отдельные настройки Electron, историю и каталоги движка;
порты локальных движков выбираются автоматически. Установленный `/Applications/OpenWork.app`
не заменяется. Для нового профиля LiteLLM подключается отдельно или импортируется
командой ниже; секреты нельзя сохранять в репозитории. Это изоляция состояния, не песочница файлов:
агент по-прежнему может изменять явно открытый проект.

Первый запуск собирает sidecar и нативные помощники и может занять несколько
минут. Изменения интерфейса обновляются через Vite; после изменения Electron
или серверного кода безопаснее остановить и повторить команду запуска.

Проверка 2026-10-29 на macOS arm64: установка frozen lockfile, сборка Swift
helpers, TypeScript/server plugins и rebuild better-sqlite3 прошли; Electron
загрузил интерфейс. Через локальный API подтверждены `running: true`,
`chatRouting: true`, движок `2.2.0`. На первом старте автоматический переход
с V1 задержался; обычный перезапуск завершил его без удаления состояния.
Подключения с API-ключами скопированы из установленного приложения через локальные
API. Наличие импортированных моделей в каталоге V2 проверено; успешный ответ
модели из этой сборки пока не проверялся.

## Копирование подключений

Оба приложения должны быть запущены. Скрипт проверяет, что источник является
установленным `/Applications/OpenWork.app`, а назначение dev-страницей localhost.
По умолчанию он только показывает имена переносимых провайдеров и моделей:

```bash
node scripts/import-local-providers.mjs
node scripts/import-local-providers.mjs --apply
```

CDP-порты по умолчанию 9224 и 9225; при изменении можно задать
`OPENWORK_SOURCE_CDP_PORT` и `OPENWORK_DEV_CDP_PORT`.
Переносятся только custom providers с base URL и API-ключом из стандартного
локального auth-хранилища. OAuth, облачная авторизация, MCP, чаты и настройки
интерфейса не переносятся. Варианты reasoning и метаданные моделей сохраняются.
Скрипт отказывается заменять одноимённый provider в dev: это импорт, не постоянная
синхронизация. Перед записью резервирует конфигурацию назначения с правами 0600
в `~/.local/state/openwork-dev-import/`; ключи не выводятся в терминал и не
сохраняются в репозитории. Исходная установка только читается.

## Подготовка на другом Mac

Требуются Xcode Command Line Tools, nvm, Node из `.nvmrc` и Bun для сборки
серверных плагинов. На этом Mac Bun 1.3.10 (как в desktop CI) установлен
только в `.data/tools/bun-darwin-aarch64/`, скрипт добавляет его в свой PATH.
Каталог `.data/` исключён из Git. На другом компьютере можно установить Bun
обычным способом; менеджером зависимостей проекта остаётся pnpm, не Bun.
Команды выполняются из корня репозитория:

```bash
source "$HOME/.nvm/nvm.sh"
nvm install
corepack enable pnpm
corepack pnpm install --frozen-lockfile
bash scripts/dev-local.sh
```

Версия pnpm зафиксирована корневым `packageManager`; не обновлять lockfile
ради локального запуска. Не нужны Den, MySQL и облачная учётная запись для
самого локального Desktop с собственным провайдером.

## План выпуска DMG

У upstream есть `package:electron:dir` для проверки распакованного приложения
и `package:electron` для упаковки, но их стандартный конфиг использует имя,
app ID и обновления официального OpenWork. Пока не устанавливать результат
поверх официальной версии и не запускать release-скрипты upstream.

Перед собственной сборкой необходимо:

1. Добавить отдельный конфиг electron-builder для форка: имя, app ID,
   URL scheme и каталог артефактов.
2. Согласовать runtime app ID с упаковкой: настройки и single-instance lock
   должны отличаться от официального приложения.
3. Отключить официальный update feed; не подменять его URL без проверки
   updater и runtime-настроек.
4. Собрать `.app`, проверить запуск и отдельный профиль, затем собрать DMG
   с публикацией, явно отключённой через `--publish never`.
5. Для распространения добавить Developer ID и notarization через секреты
   CI. Локальная неподписанная сборка не равна готовому публичному релизу.

DMG и CI ещё не реализованы и не проверены. Панель реализована для локальной
разработки: включение в Settings > Advanced > Git changes panel. Открывается
из Choose a destination или кнопкой Git на правой рейке. Состояние и ограничения
описаны в `docs/plans/git-changes-panel.md`.
