# Local Computer Use для форка

Статус: отдельная Apple Development связка подписана, статическая проверка и
живой MCP initialize от подписанного host прошли. Захват, ввод и системный
индикатор ещё не проверены. Изменена build-time настройка доверенного host;
функция управления сама по себе ещё не включена.
Платформа первого выпуска: macOS. Работа через выбранную модель и собственный
провайдер, без зависимости от установленного Codex или его закрытых пакетов.

## Результаты первого обследования (2026-10-30)

Ветка `feat/local-computer-use-preflight` создана от dev после merge upstream
синхронизации. Диагностика запускается из корня без включения захвата:

```bash
node scripts/computer-use-preflight.mjs
node --test scripts/tests/computer-use-preflight.test.mjs
swift test --package-path packages/computer-use/native --build-system native --filter BoundaryTests
```

Preflight читает подписи и число доступных сертификатов, не запускает helper,
не просит разрешений, не читает закрытые ключи, не снимает экран. Опциональные
`--host` и `--helper` проверяют указанные app bundles. Код выхода 2 означает
блокирующие предпосылки; 0 подтверждает только статические проверки файлов,
не реальную цепочку процессов, macOS permissions или возможность inference.

На текущей dev-сборке macOS 26.5.2 обнаружены:

- Host идентифицируется как `Electron`, подпись ad-hoc, Team ID отсутствует.
- Helper также ad-hoc. Ожидаемый HostTrust identifier пока upstream-значение.
- Доступен один Apple Development identity, Developer ID Application отсутствует.
  Наличие сертификата не доказывает доступ к его закрытому ключу при подписании.
- Автовыбор в prepare-computer-use-helper ищет только Developer ID Application,
  поэтому Development сам не выбирается. При ошибке явной подписи скрипт может
  перейти на ad-hoc; при signed-сценарии это надо заменить явной ошибкой.
- Fingerprint кеша helper не учитывает signing identity. Новый signed-процесс
  сборки обязан перепроверять подпись/идентичность, а не доверять одному source hash.
- 6 тестов preflight и 22 нативных BoundaryTests прошли. Это не GUI smoke test.

Следующий инженерный шаг: отдельная signed developer `.app` и helper под одной
доступной Team, собственные IDs, trusted-host ID как проверяемый build-time
параметр (не произвольный runtime env). Не переподписывать Electron в node_modules
или установленный OpenWork. Не добавлять глобальное разрешение unsigned-хостам.
Apple Development потенциально подходит для локальной проверки правила
`anchor apple generic + Team + identifier`; это необходимо доказать запуском.
Developer ID и notarization нужны отдельным этапом распространения, не DMG сейчас.

### Системный индикатор: что подтверждено

Apple документирует system Video menu, preview и прекращение sharing для
активных ScreenCaptureKit streams. Цвет/расположение и совпадение с Codex не
являются гарантией API. Текущий helper использует одноразовый
`SCScreenshotManager.captureImage`, без SCStream.

- SCContentSharingPicker доступен с macOS 14, предоставляет выбранный фильтр,
  в том числе для screenshot. `isActive` регистрирует picker, а не начинает запись.
- SCStream имеет start/stop lifecycle; пользовательский Stop возвращает
  `SCStreamError.userStopped`. Его следует связать с отзывом всей control session,
  а не автоматически запускать capture снова.
- includedWindows для строгой проверки выбора доступны с macOS 15.2, хотя
  текущий helper поддерживает 14. Для старых систем нужен отдельный путь/отказ.
- Текущие AX-masks применяются после получения изображения в helper. Нельзя
  предполагать, что системный live preview уже содержит эти маски.

Никакой поток не запускался. Не добавлять фиктивный непрерывный захват ради
значка. Runtime proof: отдельное синтетическое окно, ручной запуск, ограниченный
интервал захвата, отсутствие записи/сети, проверка системного Stop и cleanup.
Только после такого опыта выбирать streaming или screenshot-only production flow.

## Подписанная локальная dev-связка

```bash
node scripts/computer-use-signed-dev.mjs --build
node scripts/computer-use-signed-dev.mjs --probe
bash scripts/dev-signed.sh
```

Build выбирает единственную Apple Development identity либо заданную локально
`OPENWORK_LOCAL_SIGN_IDENTITY`. Существующий output не перезаписывается: перед
повторной сборкой сохранить его в другом каталоге. Использовать launcher,
не двойной клик `.app`: это подписанный dev-host, а не packaged-дистрибутив.

Проверено 2026-10-30: build завершился, статические требования подписи выполнены,
probe вернул `live_trust_passed`, `unpackaged: true`, native helper корректно
завершён. 19 Node-тестов и 23 Swift BoundaryTests прошли. Проверки не требуют
и не запрашивают Accessibility/Screen Recording. Все подписи и ключи остаются
локально; app bundle исключён из Git.

Подписанный OpenWork Local запущен через dev-signed.sh, интерфейс загружен,
движок 2.2.0 подтверждает chatRouting=true после перезапуска первого старта.
После пользовательской выдачи прав broker сообщает accessibility=true,
screenRecording=true, readiness=ready. Это чтение состояния, не захват.
Профиль отдельный; модели LiteLLM перенесены из установленного приложения
явной командой import-local-providers.mjs --apply. Все четыре модели и оба
разрешения подтверждены после полного перезапуска signed launcher. Выбрана
модель собственного провайдера, вместо встроенного Free. Секреты в Git не попали.
Локальное включение реализовано отдельным rollout `localComputerUse`, выключенным
по умолчанию. Signed launcher разрешает локальный режим, пользователь включает
Advanced > Local Computer Use. Работает только signed-out, unmanaged developer
profile и loopback server; managed organization policy не подменяется. Remote
computers и background delivery в этом режиме выключены.

В текущем подписанном профиле переключатель включён; broker подтвердил
enabled=true, target=this-mac, readiness=ready. Settings > Computer use
открыт с именем OpenWork Local Computer Use. Пользователь самостоятельно нажимает
Open Accessibility / Open Screen Recording и подтверждает доступ в macOS.
Разрешения выданы пользователем, reset TCC не выполнялся. GUI-test, индикатор и
передача наблюдений модели остаются непроверенными.

Скрипты разработки готовят отдельную копию Electron и helper в игнорируемом
`.data/computer-use-dev/`. Не устанавливают DMG, не меняют официальный OpenWork,
node_modules Electron, Keychain ACL или TCC. Подписание использует существующий
Apple Development identity; macOS может запросить доступ к ключу.

- Host: `dev.openwork.local`, отображаемое имя OpenWork Local.
- Helper: `dev.openwork.local.computer-use`, OpenWork Local Computer Use.
- Ожидаемый ID host хранится в подписанном Info.plist helper. Runtime env не
  может расширить доверие. Проверяются валидность helper, Apple anchor, Team и
  идентификатор процесса-хоста. Неподписанные/чужие hosts по-прежнему запрещены.
- Собственное приложение и его вспомогательные процессы нельзя выбирать как
  цель Computer Use, включая новые идентификаторы форка.
- В строгом режиме сборки ошибка подписи не маскируется переходом на ad-hoc.
- `bash scripts/dev-signed.sh` запускает подготовленную сборку с отдельным
  профилем и портом 15374. Обычный `dev-local.sh` остаётся без изменений.

Проверка MCP initialize доказывает только запуск доверенного процесса. Она не
запрашивает capture/input permissions и не означает, что GUI-управление включено.

## Целевой сценарий

Пользователь просит агента выполнить задачу в конкретном приложении. OpenWork
показывает разрешения и целевое окно, агент наблюдает и выполняет ограниченные
шаги. Возле этого окна виден фиолетовый индикатор OpenWork с состоянием
«просматривает», «управляет» или «пауза». Пользователь может забрать управление
или остановить работу. После остановки новые действия не выполняются.

Используем имеющиеся нативный Swift helper, computer_run/tools.ui, session broker,
ScreenCaptureKit, AX, рамку окна, виртуальный курсор и Take over/Continue/Stop.
Не создаём параллельный backend и не заменяем ограниченный code-mode произвольным
Node REPL. Скриптовые инструменты сохраняют отдельные правила подтверждения.

## PR 1: проверка нативного запуска и индикатора

1. Проверить текущую сборку и маршрутизацию инструментов без реальных действий
   в пользовательских приложениях; использовать синтетическое тестовое окно.
2. Проверить HostTrust: helper требует подписанный хост с ожидаемым bundle ID
   и общей Apple Team. Выбрать собственную идентичность форка и схему подписания
   приложения и helper. Не отключать проверку доверия ради dev-запуска.
3. Выяснить доступность подходящего сертификата без чтения/экспорта закрытых
   ключей. Если отсутствует, зафиксировать блокер и требуемое действие владельца;
   не считать ad-hoc подпись эквивалентом текущей проверки Team ID.
4. На поддерживаемой macOS сравнить отдельные снимки и выбранный пользователем
   поток захвата окна: когда появляется системный фиолетовый индикатор и как
   системная остановка захвата отзывает доступ. Не включать ненужную постоянную
   запись только ради значка.
5. Зафиксировать экспериментальные результаты и тестовые команды. Системный
   индикатор не имитировать своим UI и не обещать до проверки на устройстве.

Критерий выхода: известен воспроизводимый доверенный путь запуска и поведение
индикатора. Разрешения macOS выдаёт пользователь; настройки TCC не обходятся.
DMG, публикация релиза и notarization для распространения не входят в этап.

## PR 2: рабочая локальная функция с видимым управлением

- Зарегистрировать отдельный opt-in rollout по правилам репозитория до изменения
  поведения. Для независимого desktop дать локальное включение без Den;
  managed-политики и kill switch не обходить локальной настройкой.
- Диагностика helper/подписи/Accessibility/Screen Recording/поддержки модели.
- Привязка к конкретным приложению и окну с явным пользовательским выбором
  доступной области управления. Никакого неявного расширения на весь экран.
- Сохранить существующие инструменты и ограниченный computer_run. Перед вводом
  проверять свежесть наблюдения, окно, идентичность элемента и паузу.
- Доработать существующий presence overlay: фиолетовый бейдж с именем OpenWork,
  рамка выбранного окна, виртуальный курсор, состояния наблюдения/управления/
  паузы, Take over и Stop. Он не должен перехватывать ввод или мешать работе.
- Stop отменяет программу и захват, отпускает удерживаемый ввод; Continue после
  takeover доступен только пользователю и требует нового наблюдения. Ошибка или
  потерянный ответ не должны приводить к повторному вводу.
- Индикатор соответствует реальной сессии; после завершения исчезает. Системный
  индикатор, если подтверждён PR 1, остаётся под контролем macOS.
- Явно объяснить, что GUI-наблюдения могут передаваться выбранному AI-провайдеру:
  локальный helper не означает локальный inference. AX-маскирование не является
  гарантией обнаружения всех секретов на экране.

Приёмка: безопасный тестовый UI, чтение поля, ввод синтетического значения,
проверка результата; отмена во время выполнения; takeover и повторное наблюдение;
отказ при недоступных разрешениях/неподтверждённом хосте/устаревшем наблюдении;
отсутствие записанных экранов и секретов в репозитории. Проверить vision через
маршрут модели отдельно, не делать вывод по одному флагу Images.

UI следует DESIGN.md: P1/P7 понятные цель и состояние, P4 простое включение,
P5/S7 существующие компоненты, P11 честное подтверждение результата, S5 без
ненужных переключений панелей. Для PR приложить только синтетические скриншоты.

## PR 3: компактные состояния Accessibility

### Keep agent window in front

Opt-in `computerKeepFront` разрешается deployment/org и отдельным пользовательским
переключателем в Settings > Computer use. Локальный Den включает rollout; default
registry остаётся false. На this-mac/foreground отключает 400ms возврат в предыдущее
приложение между вызовами; это не блокировка фокуса. Ввод пользователя или смена
фокуса во время ожидания вызывают pause, продолжение только через Continue.
Stop, отмена и смена настройки завершают старый helper без replay действий.
Remote и background режимы не меняются. Terminal возврат допускается только
если пользователь не вмешался. Оптимизация не сокращает время inference сама
по себе; время нужно измерять отдельно, не обещать ускорение до 30 секунд.

Проверено: 99 JS tests broker/runtime/adapters и 97 Swift tests; app typecheck
и feature registry consistency. Signed rebuild сохранил предыдущий bundle,
live trust probe прошёл. Переключатель включён в Local, broker Ready, оба
разрешения macOS сохранились. Вызовы в пользовательские приложения для проверки
тайминга не выполнялись: скорость и поведение реального кейса ещё не измерены.

### Надёжность до оптимизации дерева

Наблюдавшийся foreground-сценарий: semantic press после отдельного observe
отклоняется как stale_observation при повторной активации окна. Receipt сообщает
completed=0, failed_step=0, may_have_acted=false; причина — изменённое состояние
или фокус, не доказанный дефект второго монитора. Снимок иногда отсутствует
из-за privacy_incomplete; нельзя выдавать это за отсутствие vision у модели.

Путь восстановления: короткий computer_run с точным semantic selector, свежим
наблюдением и live-валидацией. Повтор только атомарного press/set_value, если
receipt явно доказывает отсутствие ввода; максимум две дополнительные попытки.
Никакого replay raw refs/coordinates, keyboard typing, partial/uncertain input,
Stop/takeover. Нативные freshness, маскирование и ограничения времени не ослаблять.
Assist может избегать активации окна для подходящих AX-действий, но требует
корректного завершения старой сессии и нового наблюдения при смене режима.
Успешная работа в реальном стороннем приложении требует отдельной проверки;
unit-тесты восстановления не доказывают, что нестабильность AX устранена.

- Session-scoped node_id для сопоставления элементов, отдельный от краткоживущей
  ссылки действия. При неоднозначной идентичности выдавать новый ID.
- Полный snapshot с revision, затем added/updated/removed относительно известной
  ревизии. При смене окна, takeover, усечении/неполном скане или пропущенной базе
  сбрасывать baseline и возвращать полное состояние.
- Не трактовать усечённое дерево как удаление невидимых элементов. Контрольные
  ссылки и свежесть действий остаются обязательными.
- Сохранять полный state внутри runtime для разрешения semantic targets;
  модели отдавать компактное представление. Скриншоты запрашивать по потребности.
- Измерить объём ответов, задержку и успешность задач до/после; не обещать
  ускорение без измерения. Тесты reorder/insert/virtualization/dialogs/cancel.

## PR 4: OCR fallback

Vision OCR поверх уже проверенного и замаскированного изображения выбранного
окна. Возвращать текст, bounds, confidence и источник OCR. Не выдавать эти
результаты за AX-элементы и не ослаблять проверки координатных действий.
Использовать при недостаточном AX, а не автоматически для любого Electron.

## Вне объёма

Пассивная запись всего экрана, фоновая память, lock-screen guardian, системные
authorization plugins, перенос OpenAI-бинарников/внутренних пакетов, unrestricted
REPL, гарантированное управление скрытыми окнами любого приложения, Windows/Linux
паритет. Доступ к конкретным приложениям не тестируется без отдельного указания.

## Порядок интеграции

Отдельные feature-ветки и PR в форк, не прямой push в dev. Перед началом проверить
состояние PR синхронизации upstream и выбрать актуальную базу. Не включать этот
план или реализацию автоматически в ветку синхронизации. Каждый этап проверяется
самостоятельно; при блокере подписи UI и unit-тесты не выдаются за работающий
нативный computer-use.
