# Git Changes: дизайн-спецификация

Статус: первая read-only реализация готова в локальном форке (2026-10-29).
Базовая ревизия `dev`: `792cf59fe`. DMG и публикация не выполнялись.

## Реализовано и проверено

- Пункт Git changes в Choose a destination и кнопка на правой рейке.
- Вкладка рядом с чатом: папка текущей сессии, branch/base, суммарные и
  пофайловые счётчики, Unified/Split, сворачивание файлов.
- Authenticated read-only маршрут `/workspace/:id/git/changes` обращается
  к локальным native VCS API и использует проверенную папку сессии.
- Автообновление видимой панели, ручное обновление, отмена запросов,
  состояния ошибок/нет репозитория/нет изменений и недоступных патчей.
- Флаг выключен по умолчанию. Независимый desktop включает его в
  Advanced > Git changes panel через общий resolver; managed окружения
  используют policy организации. В текущем dev включён.
- 20 focused тестов (UI/parser/flag/client/server), app/server typecheck.
  Проверены в Electron реальные working и branch diff, Unified/Split и
  переход сессии в другую папку. Скриншоты пользовательского кода в репозиторий
  не включены.

Ограничения: нет отдельного fullscreen, сохранения Git-вкладки и выбора
base/layout между перезапусками, загрузки дополнительного контекста,
stage/unstage/discard. Working объединяет staged и unstaged. Ниже сохранён
целевой дизайн; не все его пункты уже реализованы.

## Цель и границы

Просматривать текущие изменения файлов рядом с разговором: чат слева,
вкладка «Изменения» справа в той же пристыкованной панели, что Browser.
Первый релиз только для чтения: без stage, unstage, discard, commit, checkout,
создания worktree, инициализации репозитория и автоматического fetch.
Никаких новых diff-библиотек: использовать установленный `@pierre/diffs` 1.3.5.

Фокус панели: изменённые строки, не поясняющий текст или декоративные карточки
(DESIGN P1, P2, P6, P7, S1). Панель не приписывает изменения агенту: она показывает
все изменения выбранной рабочей папки, включая изменения пользователя.

## Предлагаемое взаимодействие

1. На экране `Choose a destination` добавить пункт **«Изменения Git»** рядом
   с Browser, Files & artifacts и Library. Это основная точка входа, не только
   команда в палитре. Нажатие заменяет экран выбора содержимым Git-вкладки
   в той же правой панели; отдельное окно или переход из чата не создаётся.
   Команда «Открыть изменения» в правой панели/её навигации открывает или выбирает
   одну Git-вкладку для текущего workspace. Палитра вызывает ту же команду (S6).
   Новое сообщение, tool result или обнаружение изменений не открывают её сами (S5).
2. Обычный режим: чат слева остаётся доступным, панель справа использует существующий
   resize handle и ограничения ширины. Изменение размера не сбрасывает чат или diff.
3. «Развернуть» занимает область приложения, не создаёт окно ОС и не запускает Browser.
   «Вернуть в панель» возвращает прежнюю ширину, файл и позицию прокрутки. Чат временно
   скрыт, но не размонтируется с потерей черновика/состояния. Это расширение общего
   shell, не уже существующая возможность Git-вкладки.
4. Закрытие панели скрывает её, сохраняя вкладки. Закрытие Git-вкладки выбирает соседнюю
   по существующим правилам. Повторное открытие восстанавливает режим сравнения,
   выбранную базу, unified/split, свёрнутые файлы и scroll anchor для той же папки.
   После перезапуска восстанавливаются только настройки/ссылки, но не сохранённый patch;
   данные проверяются заново. Не переносить прежние файлы в другой workspace.
5. На узком экране использовать существующий адаптивный shell: одна полноширинная
   поверхность с явным возвратом в чат, а не две нечитаемые колонки. Чат сохраняет
   состояние. Split доступен только при достаточной ширине; временный unified не
   перезаписывает сохранённое предпочтение пользователя.

Предлагаемый состав панели:

```text
Чат слева                 | Browser | Изменения                 [закрыть вкладку]
                          | Репозиторий / рабочая папка   Ветка
                          | [Рабочая папка v] [+124 -37] [Обновить] [Развернуть]
                          | [Файлы: 4 v] [Unified | Split]          [скрыть панель]
                          | v src/panel.tsx          Изменён     +80 -20
                          |   номера строк, hunks, свёрнутый контекст
                          | v src/store.ts           Добавлен   +44 -0
                          |   следующий diff в том же потоке
```

Репозиторий, ветка и режим остаются видимыми. Полный фактический путь доступен
через tooltip/технические сведения; если известна только папка запроса, не выдавать
её за подтверждённый корень Git. Для вложенной папки явно обозначать ограниченную
область просмотра. Detached HEAD и отсутствие первого коммита показывать как состояния,
не подставлять выдуманную ветку.

- Один вертикальный scroll-контейнер на все файлы, без вертикального скролла внутри
  каждого diff. Заголовки файлов содержат полный относительный путь, статус и `+/-`;
  длинный путь сокращается визуально, полностью доступен с клавиатуры/в tooltip.
- Все небольшие diff раскрыты: содержимое является ответом (S3). Можно свернуть файл;
  меню «Файлы» переводит к его заголовку. Заголовок активного файла может быть sticky.
- Unified по умолчанию; Split показывает старую и новую версии рядом с согласованной
  вертикальной прокруткой. Номера строк и знаки добавления/удаления обязательны:
  смысл не передаётся одним цветом. Длинные строки переносятся без расширения shell.
- Контекст по умолчанию три строки. «Показать ещё контекст» раскрывает пропуски с
  сохранением scroll anchor; для отсутствующего в patch текста требуется новый запрос,
  а не чтение текущего файла вместо старой версии. Не обещать восстановить текст,
  который сервер не вернул.
- Суммарные `+/-` вычислять из полей `additions`/`deletions` файлов одного ответа diff
  выбранного режима, а не из видимых DOM-строк или независимого status. При неполных
  данных указывать неполноту.
  Не смешивать working-статистику с branch-diff. Бинарные файлы учитывать в числе файлов,
  не трактовать нулевые line counts как отсутствие изменений.

## API и смысл сравнения

Подтверждено исходниками OpenCode **v2.2.0**, а не проверкой запущенного сервера:

| Native запрос через OpenWork | Назначение |
| --- | --- |
| `GET /workspace/:id/opencode2/api/vcs` | Provider, текущая и default-ветка. |
| `GET /workspace/:id/opencode2/api/vcs/status` | Список незакоммиченных изменений. |
| `GET /workspace/:id/opencode2/api/vcs/diff?mode=working&context=3&untracked=files` | `HEAD` против текущей рабочей копии, staged и unstaged вместе, плюс untracked. |
| `GET /workspace/:id/opencode2/api/vcs/base` | Кандидат базы review; может отсутствовать или требовать явного выбора. |
| `GET /workspace/:id/opencode2/api/vcs/branch` | Локально известные локальные/remote-ветки, без fetch. |
| `GET /workspace/:id/opencode2/api/vcs/diff?mode=branch&base=<ref>&context=3&untracked=files` | Merge-base выбранной базы и HEAD против рабочей копии: коммиты ветки **и** незакоммиченные изменения. |

В UI два режима: «Рабочая папка» и «Ветка и рабочая папка». Во втором обязательна
видимая выбранная база; принять проверенный кандидат `/vcs/base` или запросить выбор.
Не выбирать молча `main` и не использовать неоднозначный default API. Native
`mode=committed` сравнивает merge-base с HEAD без dirty-файлов; это возможное
расширение, не скрытая замена `branch` в первом релизе.

Ветка Git и Git worktree не одно и то же. Смена базы только меняет сравнение,
не выполняет checkout и не выбирает другую папку. Две рабочие копии одного
репозитория получают разные cache keys. VCS-прокси смотрит на зарегистрированный
workspace, а не произвольный CWD агента. Если разговор выполняется в другой папке,
сохранять явную идентичность просматриваемой папки; предложить открыть соответствующий
workspace, не пытаться обойти серверную привязку через `location[directory]`.

`/api/session/:id/diff` сравнивает снимки хода/диапазона разговора. Он **не источник**
этой панели и не fallback при ошибке Git. Не называть панель «Изменения этого ответа».
V2 объединяет staged/unstaged, имеет статусы added/deleted/modified и использует
`--no-renames`: переименование допустимо показывать как удаление плюс добавление.
Не выдумывать индексные группы, специальный conflict-статус или rename-связи.

### Предлагаемый клиентский контракт

- Добавить типизированный read-only native VCS client поверх существующего транспорта.
  Валидировать `unknown` через Zod: envelope `{ location: { directory }, data }`,
  diff-строка `{ file, patch, additions, deletions, status, more? }`; `more` может
  быть `true`. Отдельные схемы для info/status/base/branches; без `any` и слепых casts.
- TanStack Query key: идентичность серверного подключения + фактический runtime
  workspace ID + подтверждённая directory + режим + base ref + context + untracked.
  Не использовать только session ID, basename, ветку или визуальный workspace ID.
  Не помещать токен в ключ. Смена auth scope очищает соответствующий кэш.
- До ответа использовать адрес runtime workspace; проверять envelope location и
  связывать результат с подтверждённой directory. Несоответствие текущему владельцу
  запроса не должно попадать в UI. Location API не возвращает SHA: не обещать
  атомарный снимок Git между отдельными запросами.
- Передавать `AbortSignal` до fetch; отменять при смене workspace/mode/base,
  закрытии последнего наблюдателя или отключении feature. Дополнительно проверять
  поколение/владельца ответа: поздний ответ A не рисует файлы в B.
- Обновлять при открытии, ручном «Обновить», возврате фокуса и завершении работы агента
  в том же workspace. Предложение: polling раз в 5 секунд только видимой вкладки,
  объединение повторных запросов, пауза в фоне. Не создавать новый Git watcher в R1.
- При refresh оставлять предыдущий результат только того же ключа, с временем
  последней проверки; не сбрасывать прокрутку (P11). При смене ключа показывать
  skeleton новой области. Patch хранить только в памяти, не в localStorage/логах.

## Renderer, пределы и состояния

Новый read-only компонент на `@pierre/diffs` 1.3.5 использует diff API этой версии,
не `Editor`/`EditProvider` из artifact view. До реализации проверить локальные типы
и парсер библиотеки: путь/patch, unified/split, виртуализацию и раскрытие контекста.
Не копировать single-file `cacheKey: path`: ключ renderer должен учитывать repository,
режим и ревизию содержимого. Не выполнять содержимое файлов и не вставлять его как HTML.

Сервер по умолчанию отдаёт практически полный контекст, поэтому `context=3` обязателен.
V2 ограничивает patch 10 000 000 байт на файл и суммарно; превышение может стать
пустым patch без явного `truncated`. Предлагаемый UI-бюджет: свыше 500 файлов или
2 MiB patch сначала список/свёрнутые секции и явное раскрытие; тяжёлые diff рендерить
лениво/виртуализированно, не монтировать весь текст сразу. Это не отменяет серверный
лимит и не является отсутствующей в API пагинацией.

| Состояние | Представление и действие |
| --- | --- |
| Первый запрос | Skeleton в итоговом layout; без промежуточного экрана «Подготовка» (P11). |
| Нет изменений | «Изменений нет» и «Обновить»; только после успешной проверки. |
| Не Git / неподдерживаемый provider | «В этой папке нет доступного Git-репозитория», действие выбора workspace; не выполнять init. |
| Нет базы / merge-base | «Выберите базовую ветку» или «Общая база не найдена», действие смены базы; working остаётся доступен. |
| Offline / сервер недоступен | Последний результат того же workspace, время проверки, «Повторить»; без свежих фиктивных нулей. |
| Запрет доступа / выключенная feature | Нейтральное locked-состояние с причиной и владельцем настройки (P4, C5). |
| Binary | Заголовок и статус без текстового diff, если формат patch явно подтверждает binary. |
| Пустой/неполный patch | «Текст изменений недоступен» и действие просмотра файла, когда безопасно доступно; не утверждать причину без метаданных. Это может быть лимит, metadata-only change или иной формат. |
| Ошибка парсинга одного файла | Локальная строка ошибки, «Повторить», остальные файлы доступны; raw details свёрнуты (P3, C6). |

Повтор с большим context ограничен бюджетом и может не помочь при лимите сервера;
не обещать «Показать всё» без возможности выполнить это. Удалённый файл нельзя открыть
как существующий. Переходы по путям используют существующую workspace-авторизацию;
не читать произвольные абсолютные пути из patch. Fixtures, скриншоты и логи не содержат
секретов, персональных путей, имён людей или примеров заказчиков.

## Feature flag и дизайн-система

Предлагаемый ключ `gitChangesPanel`: зарегистрировать **до кода feature**, `default: false`,
deployments cloud/self_hosted с явным локальным сценарием; заполнить обязательные
метаданные владельца при реализации. В этом документе ключ ещё не объявлен.
Локальное включение/выключение должно работать без аккаунта, Den и сети.

Это требует отдельного первого шага: текущий `useDesktopFeature` читает Den, а
`useFeatureFlagsPreferences` содержит лишь локальный `workspaceRunMode`. Предлагается
локальный адаптер rollout-хранилища для зарегистрированного ключа, передающий состояние
в общий `resolveFeature`, а не новая проверка env/localStorage в компоненте. Для локального
host используется self_hosted-контекст; default остаётся off. В управляемом контексте
приоритет kill switch/operator lock сохраняется, локальный переключатель не обходит политику.
Контракт local-first расширения registry-механизма необходимо согласовать до реализации;
существующий cloud-hook не выдавать за готовое решение. Новая обязательная cloud-зависимость
для этого viewer неприемлема.

Выключение отменяет запросы и останавливает renderer/polling, оставляет понятное locked
состояние уже открытой вкладки и не меняет файлы, Browser или чат. Повторное включение
проверяет данные заново. UI использует `@/components`/Base UI для tab/button/select/popover/
tooltip/dialog и resize primitive (P5, S7), существующие токены темы (V1–V4), lucide
в toolbar (V5), видимый focus ring и reduced motion (V6–V7). Меню закрываются по Escape
раньше панели; выход из fullscreen возвращает фокус инициатору. Focus/ARIA-поведение
не реализуется самодельными window listeners.

Обязательные acceptance tests:

- Открыть Git рядом с Browser: чат слева, нет дублей вкладки; переход назад в Browser
  работает. Его native view не перекрывает diff. Resize, fullscreen/restore, hide/reopen,
  close tab и restart сохраняют допустимые настройки, черновик и scroll anchor.
- Изменённый/добавленный/удалённый файл, вложенные пути и пробелы, CRLF, отсутствие
  newline, untracked, unborn HEAD, rename как delete/add, binary и metadata-only change.
  Staged + unstaged не удваиваются; отменяющие друг друга изменения не дают ложный diff.
- Branch-режим содержит коммиты и dirty-файлы от merge-base; выбор базы не меняет checkout.
  Missing base, detached HEAD, unrelated history и отсутствие Git дают правильные состояния.
- Суммы совпадают с ответом выбранного режима; сворачивание, виртуализация и смена
  unified/split не меняют их. Контекст раскрывается без выдуманного текста и скачка к началу.
- Медленный ответ A после перехода в B, два одинаковых basename на разных серверах,
  два worktree одного репозитория и CWD сессии вне workspace не смешивают файлы/кэш.
  Ошибка status не превращает branch-diff в пустой результат.
- 500+ файлов, 2 MiB+ и серверный лимит 10 MB: чат остаётся интерактивным, данные не
  помечаются полными ошибочно. Parser error изолирован; offline сохраняет timestamp.
- Feature off/on и kill switch во время запроса не оставляют polling; локальный
  включённый viewer работает без Den. Нет Git mutations, отправки patch в облако,
  сохранения patch на диск или вызовов session snapshot diff.
- Клавиатура, screen reader, light/dark, reduced motion, узкий viewport: все действия
  доступны, меню помещаются в окно, Escape и возврат фокуса корректны (S7, V6–V7).
